# 用語集（GLOSSARY）

このアプリのコードやドキュメントに出てくる言葉を、なるべくやさしく説明します。

## Web アプリ全般

| 用語 | 意味 |
|---|---|
| **フロントエンド / バックエンド** | ブラウザで動く部分 / サーバーで動く部分。Next.js は両方を 1 つのプロジェクトで書ける。 |
| **API** | プログラム同士がやり取りするための窓口。Supabase は「URL にリクエストを送るとデータが返ってくる」API を持っている。 |
| **環境変数** | プログラムの外から渡す設定値。このアプリでは `.env.local` に Supabase の URL とキーを書く。コードに直接書かないので、公開リポジトリにキーが載らない。 |
| **`NEXT_PUBLIC_`** | この接頭辞が付いた環境変数はブラウザにも届く。公開してよい値だけに付ける。 |
| **Cookie** | ブラウザがサイトごとに保存する小さなデータ。ログイン情報（トークン）をここに入れ、リクエストのたびにサーバーへ送る。 |
| **JWT / Claims** | ログイン情報の形式。中身（Claims）に「誰か（`sub` = ユーザー ID）」が入っていて、改ざんを見抜く署名が付いている。 |
| **リダイレクト** | 別のページへ自動で移動させること。例: 未ログインで `/me` を開くと `/login` へ。 |
| **OGP** | SNS でリンクを共有したときに出るタイトル・説明・画像の設定。 |

## Next.js / React

| 用語 | 意味 |
|---|---|
| **Next.js** | React で Web アプリを作るためのフレームワーク。ページの振り分け・サーバー処理・ビルドなどを担当する。 |
| **App Router** | `app/` フォルダの構造がそのまま URL になる仕組み。`app/login/page.js` → `/login`。 |
| **`layout.js` / `page.js`** | 共通の枠 / その URL の中身。 |
| **Server Component** | サーバーで動く部品。DB からデータを取ってから HTML を作れる。何も書かなければこれになる。 |
| **Client Component** | ブラウザで動く部品。クリックや入力に反応できる。ファイル先頭に `"use client"` と書く。 |
| **Server Action** | ブラウザから関数のように呼べる、サーバー上の関数。ファイル先頭に `"use server"`。フォーム送信や DB の書き換えに使う。 |
| **`searchParams`** | URL の `?` 以降（クエリ）。`/?country=US` なら `{ country: "US" }`。 |
| **`revalidatePath`** | 「このページの表示を作り直して」とサーバーに伝える関数。データを変えたあとに呼ぶ。 |
| **proxy（旧 middleware）** | すべてのリクエストで、ページより先に動く処理。このアプリではログイン情報の更新だけを行う。 |
| **Suspense** | 中身のデータがそろうまで、代わりの表示（スケルトンなど）を出す React の仕組み。 |
| **state（`useState`）** | 部品が覚えておく値。変わると画面が描き直される。 |
| **Transition（`useTransition`）** | 「急がない更新」の印。処理中かどうか（`isPending`）が分かるので、送信中のボタン無効化に使う。 |
| **楽観的更新（`useOptimistic`）** | サーバーの返事を待たずに、成功する前提で先に画面を変える方法。失敗したら元に戻す。リアクションが一瞬で反応するのはこれ。 |
| **ハイドレーション** | サーバーが作った HTML に、ブラウザ側で React が「動き」をつなぐこと。 |

## Supabase / データベース

| 用語 | 意味 |
|---|---|
| **Supabase** | PostgreSQL（データベース）・ログイン機能・API をまとめて提供するサービス。 |
| **PostgreSQL** | データベースの一種。データを表（テーブル）で管理する。 |
| **テーブル / 行 / 列** | Excel のシート / 1 行 / 1 列のようなもの。 |
| **主キー（PK）・外部キー（FK）** | 行を区別する ID / 別のテーブルの行を指す列。`reactions.post_id` は `posts.id` を指す外部キー。 |
| **`ON DELETE CASCADE`** | 指している先の行が消えたら、こちらの行も一緒に消す設定。投稿を消すとリアクションも消える。 |
| **UNIQUE 制約** | 同じ組み合わせを 2 回入れられなくするルール。`(post_id, user_id)` で 1 人 1 投稿 1 リアクション。 |
| **CHECK 制約** | 入れられる値の条件。例: 本文は 1〜500 文字。 |
| **インデックス** | 本の索引のようなもの。並び替えや絞り込みを速くする。 |
| **RLS（Row Level Security）** | 「この行は誰が読める・書けるか」を DB 自身が判定する仕組み。API を直接叩かれても守れる。 |
| **ポリシー** | RLS のルール 1 つ 1 つ。例: 「reactions は自分の行だけ削除できる」。 |
| **GRANT / REVOKE** | テーブルや列への権限を与える / 取り上げる。このアプリでは列単位で使い、`user_id` を誰にも読ませない。 |
| **anon / authenticated** | Supabase で、未ログインのリクエスト / ログイン済みのリクエストが使う DB 上の役割（ロール）。 |
| **トリガー** | 「行が追加されたら、この処理を自動で実行する」という仕掛け。件数の増減や 3 件通報での非表示に使う。 |
| **`SECURITY DEFINER`** | 関数を「呼んだ人」ではなく「作った人」の権限で動かす設定。読めない列を DB の中だけで扱うために使う。 |
| **RPC** | DB に作った関数を API から呼ぶこと。`supabase.rpc("my_post_ids", ...)`。 |
| **publishable key** | ブラウザに出してもよい公開用キー（旧称 anon key）。できることは RLS と権限で制限される。 |
| **secret key（service role key）** | RLS を無視できる強力なキー。このアプリでは一切使わない。 |
| **スナップショット** | ある時点の値を写し取って保存したもの。留学バッジは投稿時点の留学先・期間を `posts` に保存している。 |

## 見た目・アクセシビリティ

| 用語 | 意味 |
|---|---|
| **Tailwind CSS** | `rounded-full` `bg-accent` のような短いクラス名を組み合わせて見た目を作る CSS の道具。 |
| **テーマ（`@theme`）** | 色や角丸に名前を付けて一元管理する仕組み。`globals.css` で定義している。 |
| **レスポンシブ** | 画面の幅に合わせてレイアウトを変えること。`sm:` は「幅 640px 以上なら」。 |
| **スケルトン** | 読み込み中に出す、本物の形をまねた灰色の仮表示。 |
| **トースト** | 画面の端に数秒だけ出て消える通知。 |
| **モーダル / ダイアログ** | 画面の手前に重ねて出す小窓。開いている間は後ろを操作できない。 |
| **アクセシビリティ** | 障害の有無や環境にかかわらず使えること。キーボード操作、読み上げ、色のコントラストなど。 |
| **`aria-label` / `aria-pressed`** | 読み上げソフト向けの説明 / ボタンが押された状態かどうか。 |
| **コントラスト比** | 文字と背景の明るさの差。WCAG AA では通常の文字で 4.5:1 以上が目安。 |
| **`prefers-reduced-motion`** | OS で「動きを減らす」を選んでいる人の設定。このアプリはアニメーションを止める。 |
